# Приклад: Каталог фільмів на React

**Живе демо:** https://react-movies-example.vercel.app/

Еталонний розв'язок Арени модуля **«Королівство Реакту»**.
React 19 + Vite + react-router-dom, дані з відкритого API
[TMDB](https://developer.themoviedb.org/reference/getting-started).

Макет: [Movie Listing Web App](https://www.figma.com/design/0FpFMQzeL2Q35MOiRlgySt/Movie-Listing-Web-App?node-id=401-6827)
— сторінка **Web App** (екрани Home, Movies, TV Shows, Details Page).

> Це приклад, а не шаблон. Подивись, як розкладено відповідальність
> між файлами, і зроби свою версію.

## Як запустити

```bash
npm install
cp .env.example .env    # і встав туди свій токен TMDB (як його взяти — нижче)
npm run dev
```

Далі відкрий адресу, яку покаже Vite — зазвичай http://localhost:5173.

## Як здати

Звичайний робочий цикл, без особливих правил:

1. Заведи репозиторій і окрему гілку під застосунок.
2. Роби кілька комітів у міру роботи, а не один на все.
3. Відкрий pull request у `main` і встав посилання на нього у форму здачі.
4. Задеплой застосунок (Vercel або Netlify) і додай живе посилання
   в опис pull request і в README.

Застосунок на `BrowserRouter`, тому хостингу треба пояснити, що будь-яку
адресу віддає `index.html`. Інакше пряме відкриття `/title/movie/1`
дасть 404 хостингу. Тут лежать обидва варіанти: `vercel.json` для Vercel
і `public/_redirects` (рядок `/* /index.html 200`) для Netlify.

## Як отримати токен TMDB

Це найдовша частина інструкції, бо саме тут застрягають найчастіше.
Реєстрація безкоштовна й безстрокова, картка не потрібна.

### Крок 1. Обліковий запис

Зареєструйся на [themoviedb.org/signup](https://www.themoviedb.org/signup)
і **підтверди пошту** — лист приходить одразу.

> Поки пошта не підтверджена, сторінка налаштувань API не відкриється
> і покаже помилку без пояснення. Якщо листа немає — перевір «Спам».

### Крок 2. Сторінка API

Відкрий [themoviedb.org/settings/api](https://www.themoviedb.org/settings/api)
(це ж саме: аватар праворуч вгорі → **Settings** → пункт **API** у лівому меню).

> В офіційній документації є окреме попередження: форму реєстрації API
> **не пристосовано до телефона**. Роби це з комп'ютера.

### Крок 3. Заявка на ключ

Натисни **Request an API Key** і обери план **Developer** — він
безкоштовний. Треба буде прийняти умови використання.

Далі — анкета. Що писати студентові, у якого проєкту ще немає:

| Поле | Що писати |
| --- | --- |
| Type of Use | `Education` (або `Website` — обидва підходять) |
| Application Name | Назва твого навчального проєкту, напр. `Movie Catalog` |
| Application URL | Проєкт ще не в мережі? Пиши `http://localhost:5173` або посилання на свій GitHub |
| Application Summary | Чесно: `A personal learning project — a React movie catalog for educational purposes only` |
| Ім'я, адреса, телефон | Справжні; це лише для їхнього обліку |

Схвалення зазвичай **миттєве**, зрідка — за кілька годин.

### Крок 4. Взяти саме той рядок

Після схвалення на сторінці [settings/api](https://www.themoviedb.org/settings/api)
з'являться **два різні** значення. Це місце, де плутаються всі:

| | Вигляд | Як передається |
| --- | --- | --- |
| **API Key** | 32 символи: `a1b2c3d4e5…` | у query-параметрі `?api_key=…` |
| **API Read Access Token** | дуже довгий, починається на `eyJ` | у заголовку `Authorization: Bearer …` |

**Цьому проєкту потрібен другий — API Read Access Token.** Той, що
починається на `eyJ`. Він довгий, у три частини через крапку, і в поле
не вміщається візуально — копіюй його кнопкою, а не виділенням мишею.

> Обидва способи дають однаковий доступ до API v3 — так прямо написано
> в документації. Але заголовок кращий за параметр в адресі: усе, що
> стоїть в адресі, потрапляє в логи сервера, в історію браузера
> і в поле `Referer` при переході за посиланням. Секрет там зайвий.

### Крок 5. Вставити токен у проєкт

Відкрий `.env` (той, що зробив командою `cp .env.example .env`) і встав:

```
VITE_TMDB_TOKEN=eyJhbGciOiJIUzI1NiJ9....
```

Три речі, які варто знати:

1. **Префікс `VITE_` обов'язковий.** Vite віддає в код браузера лише
   змінні з цим префіксом. Назвеш `TMDB_TOKEN` — значення просто не
   доїде, і застосунок скаже, що токена немає.
2. **Без лапок і без пробілів** навколо `=`.
3. **Перезапусти `npm run dev`.** Файл `.env` читається один раз
   на старті; гаряче перезавантаження його не підхоплює.

### Перевірити, що токен робочий

Не вгадуй — спитай у TMDB напряму:

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer ВСТАВ_СВІЙ_ТОКЕН" \
  "https://api.themoviedb.org/3/movie/24428"
```

`200` — токен робочий. `401` — токен неправильний або скопійований
не повністю.

### Якщо щось не працює

| Що бачиш | Що сталося |
| --- | --- |
| «Немає токена TMDB…» | `.env` не створено, змінна названа без `VITE_`, або сервер не перезапущено |
| «TMDB відповів статусом 401» | Скопійовано `API Key` замість `API Read Access Token`, або токен обрізано |
| «TMDB відповів статусом 404» | Помилка в шляху запиту, не в токені |
| Порожні описи українською | Це не помилка: TMDB має переклад не для кожної стрічки |

## Структура

```
index.html               одна порожня <div id="root"> і підключення шрифтів
src/
  main.jsx               точка входу: StrictMode, ThemeProvider, BrowserRouter
  index.css              усі стилі застосунку
  api/tmdb.js            адреса, токен, перевірка res.ok — усе про TMDB
  lib/media.js           приведення відповідей TMDB до однієї форми
  hooks/useTmdb.js       базовий запит: дані, завантаження, помилка, скасування
  hooks/useDebounced.js  затримка для живого пошуку
  hooks/useMedia.js      useMediaList(вкладка, запит) і useMediaDetails(тип, id)
  context/ThemeContext.jsx  тема (темна/світла) через Context і хук useTheme
  components/
    Header.jsx           навбар і перемикач теми
    SearchField.jsx      форма пошуку: кероване поле, валідація, «Знайти»
    FilterTabs.jsx       вкладки «Усі / Фільми / Серіали»
    MediaGrid.jsx        сітка карток
    MediaCard.jsx        одна картка
    StatusMessage.jsx    завантаження / помилка / порожньо
    ScrollToTop.jsx      прокрутка вгору після переходу
    icons.jsx            спільні іконки
  pages/
    HomePage.jsx         титул, пошук, вкладки, сітка
    DetailsPage.jsx      сторінка /title/:mediaType/:id
  App.jsx                маршрути
public/_redirects        усі адреси на index.html (Netlify)
vercel.json              те саме для Vercel
```

Правило, за яким проведені межі: **компонент або малює, або керує даними,
але не обидва одночасно.** `MediaCard` не знає, звідки взявся фільм.
`useMediaList` не знає, як фільм виглядатиме на екрані.

## Головне архітектурне рішення: `lib/media.js`

У макеті три вкладки — «Усі», «Фільми», «Серіали». TMDB віддає їх
різними полями:

| | фільм | серіал |
| --- | --- | --- |
| назва | `title` | `name` |
| дата | `release_date` | `first_air_date` |
| тривалість | `runtime` (число) | `episode_run_time` (масив) |

Якби кожен компонент сам розбирався, що йому прийшло, перевірка
`item.title || item.name` розповзлася б по всьому проєкту — і зламалася б
у тому одному місці, де її забули. Тому різниця гаситься **один раз**,
у `normalizeMedia()`, а далі весь застосунок працює з однією формою даних.

Це і є найкорисніший урок цієї Арени: **дані з чужого API приводять
до свого вигляду одразу на вході, а не розбирають по місцю використання.**

## Друге рішення: що зберігати в адресі, а що — в `useState`

У застосунку два шматки стану, і живуть вони в різних місцях **навмисно**:

- **обрана вкладка — в адресі** (`/?tab=movie`);
- **текст у полі пошуку — у `useState`**.

Чому не однаково. У шапці є посилання «Фільми» → `/?tab=movie`. Поки
вкладка лежала в `useState`, це посилання не працювало: адреса
змінювалася, а сторінка лишалася на вкладці «Усі», бо компонент не має
звідки дізнатися про зміну адреси. Щойно вкладка переїхала в адресу,
запрацювали і посилання в шапці, і хлібні крихти, і кнопка «назад»,
і можливість поділитися посиланням на вкладку.

А текст пошуку в адресі був би шкідливий: він змінюється на кожне
натискання клавіші, тож слово «месники» лишило б **сім** записів
в історії — сім натискань «назад», щоб вийти зі сторінки.

Правило: **стан, який має пережити перезавантаження або потрапити
в чуже посилання, живе в адресі. Решта — у `useState`.**

## Що перевіряє ментор

Вимоги Арени і місця, де кожну з них видно в цьому прикладі.

1. **Кілька маленьких перевикористовуваних компонентів із пропсами.**
   `MediaCard`, `MediaGrid`, `FilterTabs`, `StatusMessage`, `SearchField`.
2. **Стан через `useState`, де доречно, піднятий; оновлення незмінні.**
   Текст пошуку живе в `HomePage` і спускається в `SearchField` пропсами.
   Жодного `push` чи `splice` над станом.
3. **Рендер списку зі стабільними `key`, обробка подій, умовний рендер.**
   `MediaGrid` (ключ із типу й id), кнопки вкладок, чотири стани
   в `HomePage`.
4. **Щонайменше дві сторінки на React Router, `<Link>` без
   перезавантаження, `path="*"` для 404.** `App.jsx`: головна, сторінка
   фільму й «Такої сторінки немає».
5. **Форма з керованим полем і простою валідацією.** `SearchField.jsx`:
   `value` зі стану, `onChange` оновлює його, `onSubmit` починається
   з `event.preventDefault()`, а запит коротший за два символи показує
   помилку під полем (`role="alert"`, зв'язану з полем через
   `aria-describedby`).
6. *(Бажано)* **`useEffect` + `fetch` у кастомному хуку.** `useTmdb`
   і `useMediaList` / `useMediaDetails` поверх нього.
7. *(Бажано)* **Тема або поточний користувач через Context.**
   `context/ThemeContext.jsx`: провайдер у `main.jsx`, читає його
   кнопка в `Header` через `useTheme()`, без жодного пропа.
8. *(Бажано)* **Невелике сховище для спільного стану.** Тут його
   навмисно немає, чому саме, див. «Чого тут навмисно немає».
9. **Немає помилок і попереджень у консолі**, зокрема про `key`.

## П'ять деталей, на яких найчастіше спотикаються

**1. `res.ok` перевіряється руками.**
`fetch` не кидає помилку на 404 чи 500 — він відхиляє проміс тільки коли
запит не відбувся взагалі. Без перевірки застосунок спробує намалювати
сторінку помилки TMDB як список фільмів. Дивись `api/tmdb.js`.

**2. `AbortController` в очищенні ефекту.**
Користувач швидко друкує «мес» — летять запити. Повернутися вони можуть
у будь-якому порядку, і без скасування на екрані опиняться результати
для «ме», хоча в полі написано «мес». Дивись `hooks/useTmdb.js`.

**3. Стабільний `key`, а не індекс.**
Тут ключ склеєний із типу й id: ``key={`${item.mediaType}-${item.id}`}``.
Фільм і серіал можуть мати **однаковий** `id` — вони лежать у різних
таблицях TMDB, і в списку «Усі» такі два записи дали б дублікат ключа.

**4. Токен у `.env`, `.env` у `.gitignore`, `.env.example` у репозиторії.**
Усе, що потрапило в історію Git, лишається в ній назавжди — видалити файл
наступним комітом недостатньо. `.env.example` показує ментору, яка змінна
потрібна, не віддаючи йому твій токен.

**5. Усі чотири стани видно.**
Завантаження, помилка, порожній результат і готові дані. Найчастіше
забувають про порожній результат: пошук «asdfgh» має сказати
«нічого не знайшлося», а не показати порожню сітку.

## Дебаунс: чому він тут є

У макеті поле пошуку **без кнопки**, тобто результати мають з'являтися
під час набору. Кнопка «Знайти» тут є (без неї не було б форми), але живий
пошук лишився: Enter і кнопка лише не чекають на дебаунс. Але запит на кожну літеру — це сім запитів на слово
«месники» і швидко вичерпаний ліміт TMDB.

`useDebounced` тримає два значення: те, що в полі (оновлюється миттєво,
поле не гальмує), і те, що «встоялося» (йде в запит). Уся його робота —
`setTimeout` плюс `clearTimeout` в очищенні ефекту; без `clearTimeout`
таймери накопичувалися б і дебаунсу не було б узагалі.

Це не вимога завдання, але без нього макет не реалізувати чесно.

## Форма пошуку

`SearchField` тепер справжня `<form>`, і в ній зібрано все, що Арена
просить від форми:

- **Кероване поле.** `value` приходить зі стану `HomePage`, `onChange`
  його оновлює. Поле нічого не пам'ятає саме.
- **`preventDefault` в `onSubmit`.** Без нього браузер відправив би форму
  по-старому і перезавантажив сторінку разом зі станом React.
- **Проста валідація.** Запит коротший за два символи (`MIN_QUERY_LENGTH`
  у `lib/media.js`) не відправляється, а під полем з'являється підказка.
  Та сама межа діє і для живого пошуку: одна літера показує вкладку,
  а не тисячу випадкових збігів.
- **Помилку чує читалка.** `role="alert"` оголошує текст одразу,
  `aria-invalid` і `aria-describedby` прив'язують його до поля.
  Щойно людина друкує далі, помилка зникає.

## Тема через Context

Кнопка із сонцем у шапці перемикає світлу тему. Тема живе в
`ThemeContext`: провайдер стоїть у `main.jsx`, а `Header` читає її
через `useTheme()`. Ні `App`, ні сторінки про тему не знають,
і саме для цього Context і потрібен: значення доходить туди, де його
читають, без проміжних пропсів.

Три деталі з уроку про Context:

- `createContext(null)` і перевірка в `useTheme`: компонент поза
  провайдером одразу падає із зрозумілим текстом, а не мовчки бере
  фальшиве значення.
- `useMemo` для об'єкта `{ theme, toggleTheme }`: без нього кожен рендер
  провайдера роздавав би новий об'єкт і перемальовував усіх читачів.
- Кольори перемикає CSS (`:root[data-theme="light"]` у `index.css`),
  а не React: компонентам не треба знати, яка зараз тема.

## Дрібниці, які легко проґавити

- **Прокрутка після переходу.** react-router не перезавантажує сторінку,
  тому прокрутка лишається там, де була: клацнеш десяту картку —
  і сторінка фільму відкриється прокрученою до середини. Лікує
  `ScrollToTop.jsx`.
- **Дата виходу — не `2012-04-25`.** Це формат бази даних. Людині
  показуємо «25 квітня 2012 р.» через вбудований `Intl.DateTimeFormat`,
  а машині лишаємо початкове значення в `<time dateTime>`. Пастка всередині:
  рядок без часу браузер читає як опівніч **за UTC**, а форматує вже за
  поясом користувача — тож без `timeZone: "UTC"` десь у Чикаго та сама
  стрічка вийшла б 24 квітня.
- **Роль ARIA не беруть наполовину.** Вкладки виглядають як `role="tablist"`,
  але ця роль обіцяє читалці ще й `role="tabpanel"`, `aria-controls`
  і перемикання стрілками ← →. Обіцянка без виконання гірша за мовчання:
  користувач почує «вкладка 1 з 3», натисне стрілку — і нічого не станеться.
  Тому тут звичайні кнопки з `aria-pressed`.
- **Відступ задає блок, а не його останній нащадок.** Проміжок до
  заголовка розділу колись давали вкладки своїм `margin-bottom`. Щойно
  вкладки ховалися під час пошуку — заголовок злипався з полем пошуку.
- **Адресу пише користувач.** `/title/person/5` чи `/?tab=котики` мають
  показати зрозуміле повідомлення, а не порожній екран.

## Чого тут навмисно немає

- **Кешу результатів.** Кожен запит іде в мережу. Це чесно для навчального
  проєкту; у справжньому взяли б TanStack Query.
- **Пагінації.** У макеті її немає, TMDB віддає першу сторінку — 20 записів.
- **Сховища на кшталт zustand.** Спільного стану тут мало, і в кожного
  шматка вже є дім: вкладка в адресі, текст пошуку в `HomePage`, тема
  в Context. Сховище варте свого рядка в `package.json`, коли той самий
  стан читає багато віддалених компонентів; тут таких немає.
- **Токена на бекенді.** У фронтенд-застосунку токен усе одно видно
  у вкладці Network. Для навчального проєкту це прийнятно — у справжньому
  продукті такі запити ховають за власним сервером.

## Відхилення від макета

- **Шрифт.** У макеті все набрано Poppins, але **Poppins не має кирилиці**
  (у Google Fonts у нього лише latin, latin-ext і devanagari) — українські
  літери малювалися б системним шрифтом. Тому підключено ще Montserrat:
  браузер підбирає шрифт посимвольно, тож латиниця й цифри лишаються
  в Poppins, як у макеті, а кирилиця дістається Montserrat — найближчому
  геометричному гротеску з кирилицею.
- **Логотип** намальовано вручну (два трикутники), як і іконки пошуку
  й зірочки — набір vuesax і фірмовий знак із макета не експортувалися.
- **Фон** макета — растровий шар 1440×3192 зі світляними плямами.
  Тут ті самі плями зроблено двома `radial-gradient`, щоб не тягнути
  картинку на три мегабайти.
- **Тексти українською**, дані запитуються з `language=uk-UA`.
- **Титул** у макеті — ім'я автора («MaileHereko») і опис його особистого
  списку переглянутого. Тут — назва застосунку й опис каталогу,
  бо застосунок показує популярне з TMDB, а не чийсь особистий список.
- **Кнопка «Знайти»** у полі пошуку. У макеті її немає, але без неї
  форму можна надіслати лише клавішею Enter, а про це знають не всі.
- **Світла тема.** Макет лише темний; світла тема показує Context
  і перевизначає тільки кольори.
- **Пункт «Suggest me»** з навбару не реалізовано: за ним у макеті немає
  жодного екрана, а кнопка, яка нікуди не веде, гірша за її відсутність.
- **Назва на картці обрізається** трьома крапками. У макеті назви короткі
  й в один рядок, а з TMDB приходить «Людина-павук: Додому шляху немає».
  Якби така назва переносилася, картка стала б на 24px вища за сусідні
  й рівний ряд поламався б.

### Числа, звірені з макетом

Усе нижче взято з макета, а не на око — тому в CSS стоять саме такі значення:

| | Макет |
| --- | --- |
| Ширина контенту | 1200 (поля по 120 при вікні 1440) |
| Картка | 282×480, постер 266×400, поля 8/8/16, проміжок 16 |
| Проміжки в сітці | 24 між колонками, 20 між рядками |
| Поле пошуку | 344×64, поля 12/16, іконка 24, підказка 14/16 |
| Вкладки | поля 8, кнопка 8/32, радіус 8 |
| Відступи згори | титул 80, пошук 24, вкладки 80, заголовок розділу 24 |
| Панель на банері | заходить на банер на 72, зміщена на 80 від краю |
| Нижній блок деталей | відступи по 80 з боків: 80+480+80+480+80 = 1200 |

Три місця, де легко помилитися й де це помітно:

1. **`max-width: 1200px` разом із `padding: 0 24px` дає контент 1152**, а не
   1200 — при `box-sizing: border-box` поля віднімаються від ширини. Через
   це всі чотири картки виходили вужчими за макет. Тому в `.container`
   стоїть `calc(1200px + 48px)`.
2. **Заголовок розділу в макеті сірий** (Grey/400), а не білий. Це підпис
   до сітки, а не другий титул сторінки.
3. **Опис на сторінці деталей — 20/32, а не 16/28.** Дрібниця, від якої
   сторінка виглядає геть інакше.

> Порівнювати з макетом у браузері заважає смуга прокрутки: вона з'їдає
> ~15px, тож контент стоїть на 7px лівіше, ніж у Figma. Це не помилка
> верстки — у Figma смуги прокрутки просто немає.

## Перевір себе перед здачею

1. `npm install && npm run dev` — жодної помилки в терміналі.
2. Консоль браузера порожня. Особливо: жодного `Warning: Each child in a list
   should have a unique "key" prop`.
3. Пошук «asdfgh» — має з'явитися «нічого не знайшлося», а не порожня сітка.
4. Набери щось у пошуку швидко й подивись у вкладку Network: має піти
   **один** запит, а не по одному на літеру. У режимі розробки їх буде
   два — це `StrictMode` навмисно виконує ефект двічі, щоб перевірити,
   чи вміє той прибирати за собою. Головне, щоб їх не було сім.
5. Тимчасово зіпсуй токен у `.env` — має з'явитися повідомлення про помилку,
   а не білий екран.
6. `git ls-files | grep '\.env$'` — має бути порожньо.
7. Пошукай у коді `push(`, `splice(`, `= state.` — у правильному розв'язку
   стан не мутують.
8. Натисни «Фільми» в шапці — має перемкнутися вкладка, а не лише адреса.
9. Погортай каталог, відкрий картку — сторінка фільму має відкритися згори.
10. Відкрий `/title/person/5` — має бути «такої сторінки немає»,
    а не порожній екран.
11. Звузь вікно до ширини телефона — нічого не має вилазити за край
    і не має з'явитися горизонтальна прокрутка. Перевіряй на **320px**,
    а не на 375: саме там ламаються сітки з фіксованою мінімальною
    шириною колонки.
12. Відкрий стрічку без банера (у TMDB `backdrop_path` часто `null` —
    трапляється серед свіжих серіалів) — панель із назвою має стояти
    на своєму місці, а не заїжджати під шапку.
13. Введи одну літеру й натисни «Знайти»: під полем має з'явитися
    підказка, а сторінка не має перезавантажитися.
14. Перемкни тему в шапці й онови сторінку: тема має лишитися.
15. Після деплою відкрий пряму адресу, напр. `/title/movie/24428`:
    має відкритися фільм, а не 404 хостингу.
